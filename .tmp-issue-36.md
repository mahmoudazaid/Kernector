TITLE: Separate end-user UX from operational/developer controls

## Goal

Separate end-user UX from operational/developer controls through **server-side configuration and feature flags** across all presentation adapters (Streamlit, Next.js, and future adapters).

## User story

As a product owner, I want operational and developer controls gated by server-side configuration and feature flags so end users see a focused experience while operators retain necessary controls — without treating UI hiding as a security boundary.

## Acceptance criteria

- [ ] End-user flows across presentation adapters expose only task-focused controls.
- [ ] Operational/developer controls (model overrides, system prompts, diagnostics, experimental toggles) are gated by server-side configuration and/or feature flags — not by client-only visibility.
- [ ] The same separation rules apply consistently across Streamlit, Next.js, and any other presentation adapter.
- [ ] Documentation explicitly states that **hidden Streamlit controls (or any client-hidden UI) are not a security boundary**; authorization and capability gating must be enforced server-side.
- [ ] Security-sensitive settings remain effective without degrading the primary end-user experience.
