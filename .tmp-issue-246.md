TITLE: Chat history: list, open, and continue past conversations

## Epic

#124 Next.js presentation foundation and incremental Streamlit migration

## User story

As a user, I want a list of past chats and the ability to open one and continue from where I left off so New chat does not permanently discard earlier conversations.

## Context

Today Next.js keeps a **single** browser transcript under `kernector:chat-messages:v1` (`web/lib/runtime-settings-storage.ts`). New chat clears that key. Ask already accepts turn `history` for multi-turn within the active transcript (#235). There is no conversation list or resume path.

This is **not** LangGraph agent memory (#213). Export of a conversation remains #243.

## Exact scope

- Introduce a client-local multi-conversation model (thread id, title/preview, updated-at, messages) — e.g. versioned localStorage or equivalent — migrating or superseding the single-key transcript safely.
- Chat UI: list past conversations, open one into the thread, start **New chat** without deleting others, continue ask turns on the selected thread (reuse existing `/api/v1/chat/ask` + `history`).
- Rename/delete conversation (minimum viable; confirm destructive deletes with `ConfirmDialog`).
- Document the storage key/schema version and migration from `kernector:chat-messages:v1`.
- Offline/unit tests for storage + UI selection/resume; keep architecture boundaries (no server auth requirement in v1).

## Exclusions

- Server-side / multi-device sync (likely needs #182 later)
- LangGraph checkpoint / long-term agent memory (#213)
- Chat visual polish-only work (separate UX ticket)
- JSON/CSV/PDF export (#243) beyond what history selection might later feed
- Rewriting grounded-ask domain logic

## Acceptance criteria

- [ ] User can see a list of past conversations and open one to view its transcript.
- [ ] User can send a new ask turn on an opened conversation and it appends to that thread (history sent correctly).
- [ ] New chat creates a fresh thread without wiping other saved conversations.
- [ ] User can delete (and optionally rename) a conversation with clear confirmation where destructive.
- [ ] Existing single-transcript localStorage migrates into the multi-thread store without data loss when possible.
- [ ] Tests cover storage migration, list/open/new/delete, and resume ask path without live model calls.
