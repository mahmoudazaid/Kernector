TITLE: Configure hybrid search (enable + alpha) from the Next.js Settings UI

## Context

Hybrid search (BM25 + vector) is productized (#185) but still env-only (`HYBRID_SEARCH_ENABLED`, `HYBRID_ALPHA`). Next.js settings parity (#237) explicitly deferred hybrid UI. Streamlit follow-up is #205 under epic #68; this ticket covers the supported Next.js surface.

## User story

As a Kernector user, I want to choose search type (vector-only vs hybrid) and tune BM25 weight from Settings so I can experiment with retrieval without editing `.env` or restarting.

## Scope

- Expose in Next.js Settings (`web/components/settings/SettingsPanel.tsx` / runtime settings):
  - Search mode: vector-only vs hybrid (maps to `HYBRID_SEARCH_ENABLED`)
  - BM25 weight / alpha in `[0, 1]` when hybrid is on (maps to `HYBRID_ALPHA`; `1` = BM25 only, `0` = vector only)
- Wire selections through FastAPI `/api/v1` (or ask/runtime payload) so retrieve uses UI values for the session without process restart
- Persist with other client runtime settings where appropriate; defaults stay vector-only when unset (aligned with env default `false`)
- Keep DualWrite / vector-store consistency when hybrid is toggled on or off
- Docs note UI overrides/supplements env defaults for local runs

## Acceptance criteria

- [ ] Settings UI lets the user select search type (vector-only vs hybrid) and set alpha when hybrid is enabled
- [ ] Values drive retrieve for subsequent ask turns without restarting the API process
- [ ] Default remains vector-only when the user has not opted in
- [ ] Metadata filters and relevance-threshold behaviour stay correct in vector-only mode
- [ ] Hybrid on/off keeps DualWrite / BM25 hydration consistent
- [ ] Invalid alpha rejected with clear UX / Problem Details
- [ ] Tests cover Settings → HTTP/composition wiring for on/off and alpha extremes
- [ ] OpenAPI + typed client stay green if the settings contract changes
