TITLE: Add created_at / updated_at on catalog and stored chunk metadata

## Context

Reviewer feedback: documents need timestamps when inserting and updating data in the DB.

Today `CatalogDocument` only has `uploaded_at`. There is no distinct `updated_at`, and Chroma chunk metadata does not record when a chunk was first written or last replaced.

## User story

As an operator, I want insert and update timestamps on knowledge documents and their stored chunks, so I can tell when content entered the store and when it last changed.

## Scope

- Add timezone-aware `created_at` and `updated_at` to catalog document lifecycle
- On first successful ingest/create: set both to now
- On replace/re-ingest: keep `created_at`, bump `updated_at`
- Persist the same timestamps into Chroma chunk metadata on upsert
- Surface both timestamps in the Streamlit document detail line (alongside status / chunk count)
- Keep presentation free of direct Chroma/catalog path imports (composition → application → ports)

## Acceptance criteria

- Given a new upload or corpus ingest, when storage succeeds, then catalog and chunk metadata have matching timezone-aware `created_at` and `updated_at`
- Given a document replace, when storage succeeds, then `created_at` is unchanged and `updated_at` is newer
- Given the Streamlit manage-documents panel, when a document is selected, then both timestamps are visible
- Given existing catalog rows without the new fields, when loaded, then migration/defaults are defined and documented (no silent crash)

## Out of scope

- Changing retrieval ranking
- Automatic orphan GC (#201)
- Promoting other `SourceMetadata` fields (# follow-up)
