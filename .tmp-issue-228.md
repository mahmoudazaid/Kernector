TITLE: Retire Streamlit presentation after Next.js migration

## Epic

#124 Next.js presentation foundation and incremental Streamlit migration

## User story

As a maintainer, I want Streamlit removed from the repo once Next.js has replaced it as the supported interactive UI so we no longer maintain a dual presentation stack.

## Rationale

ADR `docs/adr/0002-nextjs-presentation-migration.md` and `ARCHITECTURE.md` keep Streamlit as a peer adapter during migration. Objective retirement requires feature-parity work, dual-stack CI green (#128), and an explicit product decision. This ticket is that retirement cleanup — not the parity migrations themselves.

## Exact scope

- Confirm product decision that Next.js is the sole supported interactive UI.
- Confirm feature-parity migrations for Streamlit capabilities are complete (chat, upload/ingest, settings/controls, documents, and any remaining Streamlit-only UX).
- Remove `presentation/streamlit/` and Streamlit entrypoints (`main.py` Streamlit run path, README/ops dual-stack Streamlit commands).
- Remove the `streamlit` dependency from `pyproject.toml` / lockfile and any Streamlit-only config or assets.
- Delete or rewrite Streamlit-only tests; keep architecture/boundary coverage for the remaining presentation adapters.
- Update CI (#128 dual-stack workflow) to a Next.js + FastAPI-only presentation stack.
- Update `ARCHITECTURE.md`, ADR #0002 (or a follow-up ADR), and contributor docs so Streamlit is no longer described as a supported peer UI.
- Ensure `uv run` / documented commands no longer require or mention Streamlit.

## Exclusions

- Implementing Next.js feature pages or HTTP feature APIs (those are separate parity tickets)
- Rewriting domain/application logic
- Auth, multi-tenancy, or public deployment hardening beyond what retirement docs require

## Acceptance criteria

- No Streamlit package dependency remains in the production dependency set.
- No `presentation/streamlit` (or equivalent) modules remain in the tree.
- Documented run paths use Next.js + FastAPI only; Streamlit start commands are gone.
- CI no longer runs or documents a Streamlit presentation job.
- Architecture docs and ADR retirement criteria are updated to record the completed decision.
- Full test suite passes without Streamlit.

## Architecture notes

- Per ADR #0002: retirement is **not** part of #124 / #125 definition of done.
- FastAPI under `presentation/http/` remains the HTTP presentation adapter for Next.js.
- Application and domain layers must stay UI-framework-agnostic.

## Dependencies

- **Blocked by** feature-parity migrations:
  - #235 Migrate grounded chat to Next.js + FastAPI
  - #236 Migrate document upload/ingest UI to Next.js + FastAPI
  - #237 Migrate provider/model settings controls to Next.js + FastAPI
- **Blocked by #128** (dual-stack CI foundation — complete)
- Also requires an explicit product retirement decision (ADR #0002)
- Parent epic **#124**

## Definition of Done

- [ ] Streamlit code, dependency, and entrypoints removed
- [ ] Docs/ADR/CI updated for single presentation stack
- [ ] Tests and architecture gates green without Streamlit
