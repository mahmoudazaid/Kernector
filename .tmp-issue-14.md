TITLE: Preserve analysis results across sidebar reruns

## Problem

Changing any sidebar control reruns the Streamlit app and clears the current session because the app does not persist messages or results in `st.session_state`. This breaks ongoing ask/retrieve/tool turns and any optional Compare workflow.

## Expected behavior

Previous **user input**, conversation turns, retrieval results, and tool results remain visible across reruns, including mode/variant changes.

Shared session contracts must remain **domain-neutral**. They must not assume a Story workflow. Story comparison / Compare-mode state may exist only as explicitly **Software Delivery pack-owned** presentation state when that pack is enabled.

## Acceptance criteria

- [ ] Session history (user input, conversation, retrieval outcomes, tool outcomes) is stored in `st.session_state`.
- [ ] Switching prompt variants or modes does not clear the latest user input/conversation/result.
- [ ] Existing results render on rerun without requiring the user to re-enter input.
- [ ] Shared session keys/contracts do not hard-code Story-only fields; any Compare/Story-analysis state is isolated behind the Software Delivery pack presentation path.

## Notes

- Review finding: usability point 1.
- Suggested direction: maintain a messages/results list plus a render loop.
