TITLE: Epic: Software Delivery Intelligence domain pack

## Goal

Optional **Software Delivery Intelligence** domain pack built on the generic knowledge foundation (#68).

This epic owns domain-specific prompts, scoring, workflows, and evaluation for software-delivery interpretation — not the reusable core pipeline. Story analysis and interview preparation remain **one optional sub-workflow** inside this pack, not the whole product and not part of shared core contracts.

## Product intent

Kernector is a domain-agnostic, multi-source knowledge foundation. This pack consumes retrieved evidence; it does not own connectors, ingest, or retrieval.

Complementary **source kinds** (Story, test, Confluence, SRS, OpenAPI/Swagger, code, and future kinds) are evidence inputs — not separate domains and not shared-core entity types. Business domains (Software Delivery, HR, legal, …) live in optional packs.

## Scope

* Executable pack code under `packs/software_delivery/` (prompts, tools, pack-local contracts/policy)
* Multi-source evidence workflows: analyze requirements / Story, risk scoring, test generation, Markdown export, and related UI surfaces when enabled
* Interview-prep / Story-analysis prompts and example corpus as optional pack content
* Pack-local evaluation slices that assume Software Delivery semantics
* Streamlit or Next.js experiences that appear only when this pack is enabled

## Architecture boundary

* Shared `domain/`, `application/`, `infrastructure/`, and neutral presentation must **never import** this pack
* Composition loads the pack **lazily** when enabled; the core must boot and operate with the pack **disabled**
* Connectors and retrieval remain outside the pack (foundation #68 and future connector work)
* Tools consume a retrieved evidence bundle via generic `SourceReference` / opaque tool invocation; a new source kind must not require a new shared-core contract or a new risk tool

## Not in scope

* Generic ingest/chunk/retrieve/catalog infrastructure (EPIC #68)
* External connector implementations (future Source Connectors epic, issue TBD)
* Project workspace / authorization model (future workspaces epic, issue TBD)
* Treating Story (or any single source kind) as the platform product model
