TITLE: Inspect stored chunks per document in Streamlit

## Context

Reviewer feedback: load separately how each chunk looks like.

Today the manage-documents UI shows `chunk_count` only. There is no port/use-case to list chunks by `source_id`, and operators cannot see chunk index, text, or metadata after ingest.

## User story

As an operator, I want to open a selected document and inspect each stored chunk, so I can verify chunking quality and provenance without querying Chroma by hand.

## Scope

- Extend `VectorStore` (and Chroma adapter) with a list-by-source primitive that returns stored `DocumentChunk` values (content + metadata + index)
- Application use case / contract to list chunks for one `SourceReference`
- Composition wiring; presentation calls composition only
- Streamlit: for a selected catalog document, expander or section listing each chunk (index, content preview/full text, key metadata)
- No embedding or LLM calls on this path

## Acceptance criteria

- Given an ingested document, when listed by source, then chunks return in index order with content and provenance
- Given the Streamlit manage-documents panel, when a ready document is selected, then each chunk is visible individually
- Given a missing/unknown source, when listed, then the UI shows an empty/clear state without crashing
- Given tests, when run offline with stub/real Chroma, then list-by-source is covered without live OpenRouter calls

## Out of scope

- Editing chunk text in place
- Changing chunking strategy
- Orphan wipe (#201)
