TITLE: Stop embedding rejected values via {value!r} in domain/application validation errors

## Context

Follow-up from PR #229 / #81 HTTP Problem Details mapping.

HTTP no longer forwards `str(exc)` for `ApplicationValidationError` / `DomainValidationError` (group 9 → 500 fixed operational sentence). The underlying raise idiom still embeds rejected values:

- Dominant pattern: `f"{field} must be X, got {value!r}"`
- ~30 of 45 `ApplicationValidationError` sites and ~12 of 18 `DomainValidationError` sites

Representative sites:

- `application/contracts.py:222` — `history items must be Message, got {item!r}` (conversation content)
- `application/contracts.py:133` — `metadata_filters values must be strings, got {filter_value!r}` (caller input)
- `domain/knowledge.py:120` / `:148` — `chunk must be a DocumentChunk, got {self.chunk!r}` (corpus text)
- `application/manage_documents.py:121` — `generated source_id {source_id!r} already exists`
- `domain/models.py:19` — `role must be one of [...], got {self.role!r}`

Those strings remain on `__cause__` / logs and any future adapter that reuses `str(exc)`.

## User story

As a Kernector engineer, I want validation exceptions to carry safe, field-oriented messages (or typed codes) so logs and any presentation path cannot accidentally leak corpus, history, or filter payloads.

## Exact scope

- Replace `{value!r}` / content-embedding raise messages across `domain/` and `application/` with safe fixed or field-name-only text (or structured error codes).
- Keep enough signal for tests and operators without echoing payloads.
- Update tests that assert on the old verbatim messages.

## Exclusions

- HTTP/Streamlit mapping changes (already aligned for domain validation on the HTTP side).
- New user-facing 4xx exception types for upload size (separate ticket).

## Acceptance criteria

- No domain/application validation raise embeds full `repr` of Message, DocumentChunk, filter values, or document content.
- Offline tests cover representative former leak sites.
- Architecture/error-taxonomy docs note the safe-message convention.
