TITLE: EPIC: Next.js presentation foundation and incremental Streamlit migration

## Goal

Establish Next.js as Kernector’s future web presentation layer while preserving Clean Architecture, keeping Streamlit operational during an incremental migration, and providing reusable foundations on which Dashboard, Settings, Chatbot, document management, and other pages can later be built.

## Non-goals (this epic)

- Dashboard metrics, charts, quotas, storage calculations, or retention behavior
- Settings fields, provider/secret UX, or model selection product behavior
- Chat interface, streaming, conversation persistence, citations, or retrieval behavior
- Authentication, authorization, multi-tenancy, billing, or public deployment
- Rewriting Python domain/application logic in TypeScript
- Removing Streamlit before separately approved feature-parity tickets are complete

## Target architecture

```text
Next.js (presentation) ──HTTP──> FastAPI adapter (presentation)
                                      │
                                      ▼
                                 composition
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
              application                         infrastructure
                    │                                   │
                    └───────────────► domain ◄──────────┘
```

Streamlit remains a peer presentation adapter until feature-parity migrations are approved separately.
